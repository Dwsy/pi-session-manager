# Tool Style Toggle Feature ## Overview Added a controllable toggle to disable the style (green background and border) on successful tool execution and the top/bottom margins when tool output expands. ## Changes ### 1. Settings Type (`src/components/settings/types.ts`) Added new field in `appearance` settings: ```typescript appearance: { // ... other fields disableToolSuccessStyle: boolean } ``` Default value: `false` (keep original style) ### 2. Settings UI (`src/components/settings/sections/AppearanceSettings.tsx`) Added new setting item: - **Label**: Disable Tool Success Style - **Description**: Disable green background and border on successful tool execution for cleaner tool cards - **Type**: Checkbox ### 3. CSS Variable Control #### `src/index.css` ```css /* Tool execution success style - controlled via CSS variable */ .tool-execution.success { background: var(--toolSuccessBgOverride, var(--toolSuccessBg, rgba(var(--success-rgb), 0.08))); border-color: var(--toolSuccessBorderOverride, rgba(var(--success-rgb), 0.22)); } /* Tool output expanded margin - controlled via CSS variable */ .tool-output-wrapper.collapsible.expanded { margin-top: var(--toolOutputExpandedMargin, 8px); margin-bottom: var(--toolOutputExpandedMargin, 8px); } ``` #### `src/styles/session.css` ```css .tool-output-wrapper.collapsible.expanded { margin-top: var(--toolOutputExpandedMargin, 8px); } ``` ### 4. Theme Utils (`src/utils/piTheme.ts`) Added new CSS variables to `OVERRIDE_VARS`: - `--toolSuccessBgOverride` - `--toolSuccessBorderOverride` - `--toolOutputExpandedMargin` ### 5. Custom Hook (`src/hooks/useToolStyles.ts`) Created new hook to dynamically control CSS variables based on settings: ```typescript export function useToolStyles() { const { settings } = useSettings() const disableSuccessStyle = settings.appearance.disableToolSuccessStyle useEffect(() => { const root = document.documentElement if (disableSuccessStyle) { // Disable success style root.style.setProperty('--toolSuccessBgOverride', 'var(--bg-subtle)') root.style.setProperty('--toolSuccessBorderOverride', 'rgba(var(--accent-rgb), 0.12)') root.style.setProperty('--toolOutputExpandedMargin', '0px') } else { // Enable default style root.style.removeProperty('--toolSuccessBgOverride') root.style.removeProperty('--toolSuccessBorderOverride') root.style.removeProperty('--toolOutputExpandedMargin') } return () => { root.style.removeProperty('--toolSuccessBgOverride') root.style.removeProperty('--toolSuccessBorderOverride') root.style.removeProperty('--toolOutputExpandedMargin') } }, [disableSuccessStyle]) return { disableSuccessStyle } } ``` ### 6. App Integration (`src/App.tsx`) Called `useToolStyles()` hook in App component: ```typescript useAppearance(); useToolStyles(); ``` ### 7. Component Logic (`src/components/EditExecution.tsx`) Modified status class application logic: ```typescript const statusClass = isError ? 'error' : !disableSuccessStyle ? 'success' : '' return ( <div className={`tool-execution ${statusClass}`.trim()} id={`entry-${entryId}`}> ``` ### 8. Internationalization #### `src/i18n/locales/zh-CN/settings.ts` ```typescript appearance: { // ... other fields disableToolSuccessStyle: 'success', disableToolSuccessStyleDesc: 'successgreen background and border，', enabled: '', } ``` #### `src/i18n/locales/en-US/settings.ts` ```typescript appearance: { // ... other fields disableToolSuccessStyle: 'Disable Tool Success Style', disableToolSuccessStyleDesc: 'Disable green background and border on successful tool execution for cleaner tool cards', enabled: 'Enabled', } ``` ## Usage 1. Open Settings panel 2. Navigate to **Appearance** section 3. Find **Disable Tool Success Style** option 4. Check to disable success style, uncheck to restore default style ## Effects ### Before (Default) - Tool execution success: Green background + Green border - Tool output expanded: 8px top/bottom margin ### After - Tool execution success: Normal background + Default border (consistent with other states) - Tool output expanded: No margin (more compact) ## Technical Implementation Uses **CSS Variable + React Hook** combined approach: 1. **CSS Variable Layer**: Cascading control via `var(--toolSuccessBgOverride, fallback)` 2. **Hook Layer**: `useToolStyles` listens for settings changes and dynamically updates CSS variables 3. **Component Layer**: `EditExecution` decides whether to apply `success` class based on settings This design avoids directly modifying CSS files and enables runtime dynamic switching. ## Related Files - `src/components/settings/types.ts` - Settings type definitions - `src/components/settings/sections/AppearanceSettings.tsx` - Settings UI - `src/hooks/useToolStyles.ts` - Style control hook (new) - `src/hooks/useSettings.ts` - Settings hook - `src/utils/piTheme.ts` - Theme utils - `src/index.css` - Main stylesheet - `src/styles/session.css` - Session styles - `src/components/EditExecution.tsx` - Tool execution component - `src/App.tsx` - App entry - `src/i18n/locales/*/settings.ts` - i18n files ## Design Principles > 「True simplicity is not removing features, but making control more controllable.」 This feature follows these principles: 1. **Controllability**: Users can choose whether to enable 2. **Non-destructive**: Default keeps original style 3. **Performance friendly**: Uses CSS variables instead of forcing re-renders 4. **Type safe**: Complete TypeScript type support
