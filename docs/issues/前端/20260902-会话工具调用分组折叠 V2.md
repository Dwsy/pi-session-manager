# Issue: 会话工具调用分组折叠 V2

## Goal

在保留现有整轮折叠的同时，新增参考 Grok 连续工具调用 run 的 V2 分组折叠，并将 V2 设为默认折叠方式。

## 背景/问题

当前 Conversation mode 会把一个用户请求到最终 assistant 回复之间的所有中间项整体折成一个摘要，工具调用、thinking 与其他中间事件没有边界，展开粒度过粗。Grok 的滚动区会先识别连续可分组工具 run，thinking 可透明/并入，非工具内容会断组，并允许每个 run 独立展开。

## 验收标准 (Acceptance Criteria)

- [x] WHEN Conversation mode 开启且未保存折叠方式，系统 SHALL 默认使用“工具调用分组” V2
- [x] WHERE 会话设置，系统 SHALL 可在“整轮折叠”和“工具调用分组”之间切换
- [x] WHERE V2 主会话视图，系统 SHALL 仅折叠连续工具调用 run，普通 assistant 文本、模型切换及其他断点保持可见
- [x] WHERE V2 run 含 thinking/toolResult 透明项，系统 SHALL 不让它们错误拆散连续工具调用组，并且摘要只统计工具调用
- [x] WHEN 用户展开或搜索/跳转命中某个 V2 组内条目，系统 SHALL 只展开对应组
- [x] WHEN 选择“整轮折叠”，系统 SHALL 保持现有整轮摘要和整轮展开行为

## 关键决策

| 决策 | 理由 |
|------|------|
| 新模式命名为“工具调用分组”，旧模式命名为“整轮折叠” | 直接反映两种折叠粒度，设置里易于理解和切换 |
| `conversationFoldMode` 默认 `toolGroups`，缺失或非法配置都归一化到 V2 | 新用户与旧配置都默认获得 V2，同时明确保留合法 `wholeTurn` 值 |
| V2 复用 Grok 的 member / thought / transparent / break run 语义 | 连续工具调用可成组；finished thinking 可并入；toolResult/流式 thinking 不误拆组；可见文本与非消息事件明确断组 |
| 摘要只统计工具成员并保持首次出现顺序 | 与 Grok 的工具 run 标签语义一致，避免 thinking/toolResult 污染摘要 |
| 复用现有摘要、Review、SessionEntryRenderer 和样式 | 避免复制工具卡与展开渲染逻辑，控制变更面 |
| 暂不引入 Grok 的长 run 截断预算折叠 | 本任务聚焦工具调用分组；截断预算是独立的超长列表策略，不属于当前需求 |
