# Issue: 清理回顾界面 AI-slop

## Goal

将 Dashboard 回顾从全屏故事轮播重构为克制、事实优先的单页周期报告，同时保留既有周期触发与自动开关行为。

## 背景/问题

回顾扩展曾引入自动播放、场景进度、动态色相、环境光斑、噪点、成就稀有度、分享卡和大量拟人化旁白。它与 Pi Session Manager 的高信息密度开发工具定位冲突，并迫使用户逐幕浏览本可直接扫描的数据。

## 验收标准 (Acceptance Criteria)

- [x] WHEN 打开任意回顾周期，系统 SHALL 在单页报告中直接展示核心统计与主要活动信号
- [x] WHERE Dashboard 回顾界面，系统 SHALL 不使用自动播放、故事场景、环境光斑、噪点、稀有度/成就式视觉
- [x] IF 周期无会话或统计加载失败，THEN 系统 SHALL 提供清晰的空状态或重试操作
- [x] WHERE 自动回顾设置，系统 SHALL 保持周/月默认关闭、年/半年默认开启、季度不自动触发
- [x] WHERE demo provider 请求 scoped stats，系统 SHALL 只聚合传入会话，避免周期报告混入全局统计

## 关键决策

| 决策 | 理由 |
|------|------|
| 使用现有 `DashboardDialog` 承载回顾 | 与 Dashboard 其他详情交互一致，避免全屏“体验页” |
| 单页直接展示统计而非故事轮播 | 用户目标是快速理解周期活动，不是观看自动叙事 |
| 删除旧故事运行时而非仅隐藏 | 避免保留约 5k 行无用复杂度、文案和视觉债务 |
| 保留周期触发/默认开关逻辑 | 行为变更已独立实施，本次只清理呈现并验证没有回退 |
| 修复 demo provider 的统计 scope | 浏览器验证暴露出 9 个周期会话混入 33 个全局会话统计，属于 provider 契约违约 |
| “Active days”改为“Session days” | 直接从周期 scoped sessions 计算，口径可验证且不依赖 demo 固定 30 天 heatmap |
