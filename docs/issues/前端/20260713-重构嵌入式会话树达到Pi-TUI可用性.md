# Issue: 重构嵌入式会话树，达到 Pi TUI 可用性

## Goal

重构会话查看器内部 `.session-sidebar.session-sidebar--open.session-sidebar--embedded` 的会话树，使其在树形辨识、分支折叠、搜索过滤、快捷键和方向键导航方面至少达到 Pi TUI `/tree` 的可用性，并利用桌面 UI 的空间提供更清晰的视觉反馈。

> “A user interface is well-designed when the program behaves exactly how the user thought it would.” — Joel Spolsky

## 严格范围

### 本 Issue 包含

- `src/components/session-viewer/SessionViewerSidebar.tsx` 内嵌 Sidebar 的树区域。
- `src/components/session-tree/SessionTree.tsx` 及其内部组件。
- `src/utils/session-tree.ts` 的树模型、可见树投影和轨道前缀。
- `src/styles/_tree.less` 中仅作用于嵌入式会话树的样式。
- SessionTree 相关单元测试、交互测试和视觉夹具。

### 本 Issue 不包含

- 应用主侧栏 `AppDesktopSidebar`。
- 项目/会话列表 `ProjectList`、`SessionList`、`SessionListByDirectory`。
- Dashboard、Kanban、Favorites、Settings。
- Flow / Hierarchy 的实现重构。
- 修改 Pi JSONL 文件格式、后端 API 或插件 SDK。

Flow / Hierarchy 只能在本 Issue 中记录共享模型边界，必须另开后续 Issue 实施。

## 问题陈述

当前 Sidebar 具备部分树数据，但没有形成可靠、可操作的树形界面：

| 维度 | 当前状态 | 目标状态 |
|------|----------|----------|
| 树形辨识 | CSS 独立线段、圆点、图标和缩进互相分离，难以追踪父子关系 | `│ / ├─ / └─` 轨道连续，分叉和收口一眼可见 |
| 单子链 | 深度表达与真实分叉混杂，容易持续右漂 | 复用 Pi 逻辑，普通单子链不增加视觉深度 |
| 深层树 | `stickyShift` 裁掉祖先层级 | 保留祖先轨道，只截断或横移正文 |
| 折叠 | 仅分支节点出现有限 disclosure，缺少完整状态机和快捷键 | 鼠标、方向键和快捷键都能折叠/展开；折叠数可见 |
| 选择与导航 | active、selected、in-path 语义竞争 | active path、current leaf、keyboard focus、selected target 明确分离 |
| 搜索 | 搜索结果切换会触发导航，缺少树内焦点语义 | 输入即过滤；上下一个结果只移动树焦点，Enter 才打开 |
| 过滤 | 五个按钮占空间，过滤后树结构不够直观 | 快捷切换过滤模式；过滤后重建最近可见祖先轨道 |
| 键盘 | 树容器缺少完整 roving focus 与树导航规则 | 上下移动、左右折叠/跳父子、Enter 打开、Esc 分层退出 |
| 信息密度 | Thread context、深度提示、详情面板挤压树区域 | 树本身优先，占据 Sidebar 主要高度 |
| 无障碍 | 行主要依赖 click handler | 标准 `tree/treeitem/group`、roving tabindex 和状态说明 |

## 设计原则

1. **逻辑与 UI 分离**：树状态机不读取 DOM，不生成 CSS；UI 不重新推导父子关系。
2. **可见树是投影，不是真实树**：搜索、过滤和折叠只改变 visible projection，不修改 JSONL 拓扑。
3. **位置与分支分离**：键盘焦点、查看目标、active leaf、active path 是不同状态。
4. **轨道优先于装饰**：先保证 `│/├/└` 连续，再考虑图标、颜色和徽章。
5. **渐进披露**：默认隐藏低价值元数据；详情按需出现，不常驻挤压树。
6. **至少不弱于 TUI**：Pi TUI 已支持的搜索、过滤、折叠、标签和键盘能力，不得在桌面版本丢失。
7. **桌面增强而非照搬 ANSI**：保留 Pi 的信息模型，使用 Web 的 focus、tooltip、scroll 和响应式能力。

## 架构：逻辑层与 UI 层分离

### A. 逻辑层：SessionTreeModel

逻辑层负责从 JSONL entries 得到不可变树模型，不依赖 React。

```ts
interface SessionTreeNode {
  readonly id: string
  readonly entry: SessionEntry
  readonly parentId: string | null
  readonly childrenIds: readonly string[]
  readonly label?: string
}

interface SessionTreeModel {
  readonly nodesById: ReadonlyMap<string, SessionTreeNode>
  readonly rootIds: readonly string[]
  readonly activeLeafId: string | null
  readonly activePathIds: ReadonlySet<string>
}
```

职责：

- 规范化 `None/null/缺失 parent/self-parent`。
- 按 timestamp 稳定排序 children。
- 当前 active subtree 在同级中优先。
- 构造 active root-to-leaf path。
- 解析 label 和 toolResult 的导航 target。
- 不包含搜索、折叠、选中和 DOM 状态。

### B. 状态层：SessionTreeController

```ts
interface SessionTreeViewState {
  readonly filterMode: TreeFilterMode
  readonly searchQuery: string
  readonly foldedIds: ReadonlySet<string>
  readonly focusedId: string | null
  readonly selectedId: string | null
  readonly searchMatchIds: readonly string[]
  readonly searchMatchIndex: number
}
```

职责：

- 处理 keyboard action，而不是直接处理 key code。
- 管理 focused / selected / folded / query / filter。
- 当当前焦点被过滤或折叠隐藏时，回退到最近可见祖先。
- Esc 分层退出：清搜索 → 清临时折叠/过滤状态 → 关闭 Sidebar。
- 搜索结果 next/previous 只移动焦点和滚动，不自动打开消息。

建议先定义语义 Action：

```ts
type TreeAction =
  | { type: "MOVE_PREVIOUS" }
  | { type: "MOVE_NEXT" }
  | { type: "FOLD_OR_PARENT" }
  | { type: "UNFOLD_OR_CHILD" }
  | { type: "PAGE_PREVIOUS" }
  | { type: "PAGE_NEXT" }
  | { type: "OPEN_FOCUSED" }
  | { type: "SET_QUERY"; query: string }
  | { type: "CYCLE_FILTER" }
  | { type: "TOGGLE_FOLD"; id: string }
```

### C. 投影层：VisibleSessionTree

投影层组合 Model + ViewState，生成 UI 唯一消费的数据：

```ts
interface VisibleTreeRow {
  readonly id: string
  readonly entry: SessionEntry
  readonly visibleParentId: string | null
  readonly visibleChildrenIds: readonly string[]
  readonly prefix: string
  readonly depth: number
  readonly isLast: boolean
  readonly isFoldable: boolean
  readonly isFolded: boolean
  readonly hiddenDescendantCount: number
  readonly isActiveLeaf: boolean
  readonly isInActivePath: boolean
  readonly isFocused: boolean
  readonly isSelected: boolean
  readonly isSearchMatch: boolean
}
```

投影顺序必须固定：

1. 从真实树应用 filter。
2. 应用 search token AND 匹配。
3. 将剩余节点连接至最近可见祖先。
4. 应用 folded descendants 隐藏。
5. 重新计算 visible parent/children。
6. 运行 Pi flatten 算法。
7. 生成 `│ / ├─ / └─` prefix。
8. 校正 focusedId。

禁止 React 组件自行计算 indent、gutters、最近祖先或 active path。

### D. UI 层

建议组件结构：

```text
SessionViewerSidebar
└─ SessionTreeShell
   ├─ SessionTreeSearch
   ├─ SessionTreeToolbar
   │  ├─ FilterModeControl
   │  └─ TreeViewPluginActions
   ├─ SessionTreeList
   │  └─ SessionTreeRow
   │     ├─ TreePrefix
   │     ├─ ActivePathMarker
   │     ├─ EntrySummary
   │     └─ FoldIndicator
   └─ SessionTreeStatus
```

UI 层职责：

- 渲染投影结果。
- 将鼠标和键盘事件翻译成 TreeAction。
- roving tabindex、scrollIntoView、tooltip、ARIA。
- 不通过 CSS 推导树结构。

## 树轨道规范

轨道必须与 Pi TUI / export 的逻辑一致。

### 基本形态

```text
  user: root prompt
  assistant: response
  ├─ user: branch A
  │  assistant: response A
  └─ user: branch B
     assistant: response B
```

### 规则

- 每一层固定宽度，使用等宽字体。
- 祖先仍有后续兄弟：`│  `。
- 当前节点不是最后兄弟：`├─ `。
- 当前节点是最后兄弟：`└─ `。
- 普通单子链不持续增加缩进。
- 真正分叉时才增加视觉深度。
- 多根结构使用虚拟根语义，但不显示虚拟根节点。
- 过滤后用“最近可见祖先”重新计算轨道。
- prefix 应来自逻辑层字符串或结构化 segment，不允许 CSS `:before` 猜测。

### 折叠表达

折叠符号必须位于 connector 与正文之间，不能破坏轨道连续性：

```text
├─⊟ user: expanded branch
└─⊞ user: collapsed branch  · 12 hidden
```

Web UI 可用 Chevron，但占位宽度必须固定，且不能让有/无 children 的正文起点跳动。

## 状态视觉语义

| 状态 | 视觉编码 | 禁止做法 |
|------|----------|----------|
| active path | 轨道或 marker 使用 Accent | 给整条路径大面积高饱和背景 |
| active leaf | 实心 marker + `current` 文本提示 | 只靠字体加粗 |
| keyboard focus | 清晰 focus ring/行框 | 与 selected 使用同一颜色和形态 |
| selected target | 低对比背景 + 左侧细线 | 改变字体粗细导致布局偏移 |
| search match | 文本片段高亮 | 整行固定亮蓝背景 |
| non-active branch | 正常可读文字、较弱轨道 | 整行 opacity 0.5 以下 |
| folded branch | disclosure + hidden count | 仅改变 Chevron 方向，无数量反馈 |

## 键盘交互规范

### 树列表聚焦时

| 按键 | 行为 |
|------|------|
| `↑` | 移动到上一个 visible row |
| `↓` | 移动到下一个 visible row |
| `←` | 当前可展开且已展开时折叠；否则移动到 visible parent |
| `→` | 当前已折叠时展开；否则移动到第一个 visible child |
| `Enter` | 打开 focused entry，对话区定位到 target |
| `Space` | 只选择/预览 focused entry，不打开 |
| `PageUp` | 向上移动一个 viewport |
| `PageDown` | 向下移动一个 viewport |
| `Home` | 第一条 visible row |
| `End` | 最后一条 visible row |
| `Shift+L` | 编辑/清除节点 label（若现有能力允许） |
| `Shift+T` | 切换 label timestamp（对齐 Pi TUI） |
| `Ctrl+O` / `Cmd+O` | 循环过滤模式，具体平台冲突需验证 |
| `Esc` | 按层级清除搜索/临时状态；无临时状态时关闭 Sidebar |

### 搜索框聚焦时

| 按键 | 行为 |
|------|------|
| 输入 | 实时更新 AND token 搜索 |
| `↑` / `↓` | 上一个/下一个匹配项，不打开消息 |
| `Enter` | 打开当前匹配项 |
| `Esc` | 清空搜索；再次 Esc 将焦点返回树 |
| `Cmd/Ctrl+F` | 当 Sidebar 已打开时聚焦树搜索框 |

所有快捷键必须集中在专用 hook/controller，禁止分散在多个 `useEffect`。

## 搜索规范

- 空白分词，所有 token 必须命中。
- 支持 quoted phrase，沿用 `parseQuotedQuery()`。
- 搜索字段至少包括：label、role、正文、tool name、命令、summary、model、entry type。
- 结果计数显示 `current / total`。
- 当前匹配项与普通匹配项视觉不同。
- 清空搜索后恢复此前 focusedId；若不存在则回到 active leaf 或最近可见祖先。
- 搜索不得自动改变 active leaf。
- 搜索不得自动打开消息。

## 过滤规范

保留并对齐 Pi 的五种模式：

1. `default`
2. `no-tools`
3. `user-only`
4. `labeled-only`
5. `all`

要求：

- 提供键盘循环。
- 工具栏不应被五个同权按钮永久占满；可使用紧凑 segmented control、select 或 command menu，视觉方案在实现前确认。
- 切换过滤时保持最接近原 focusedId 的可见祖先。
- 过滤只影响投影，不影响 active path 数据。
- 状态栏明确显示当前模式和 visible/total 数量。

## 折叠规范

- 任何存在 visible children 的节点都可折叠，不限于 `children.length > 1`。
- 折叠隐藏全部 visible descendants。
- active leaf 的祖先路径默认自动展开。
- 搜索开始时临时展开命中路径；清空搜索后恢复用户折叠状态。
- 过滤模式切换不应永久清除用户折叠状态。
- 折叠节点显示隐藏后代数量。
- 提供“全部折叠到分支点”和“展开 active path”命令，但不需要常驻大按钮。

## Sidebar UI 布局

目标宽度范围来自现有控制器：280–720px，默认约 520px。

```text
┌ Search session tree...      3/18 ↑ ↓ × ┐
├ [No tools ▾]  Flow  Hierarchy          ┤
│ Thread: latest user prompt...           │  可选，最多一行
├─────────────────────────────────────────┤
│ • user: root prompt                     │
│   assistant: response                   │
│   ├─⊟ user: branch A                    │
│   │  assistant: response A              │
│   └─⊞ user: branch B · 12 hidden        │
│      assistant: current response        │
│                                         │
├ no-tools · 28/787 · current d1160b05 ───┤
```

### 优先级

1. 树列表占据绝大部分高度。
2. Search 固定顶部但保持紧凑。
3. Filter / plugin view actions 单行。
4. Thread context 若保留只能单行，并允许关闭。
5. 常驻 JSONL detail pane 移除，改为 tooltip、popover 或按需预览。
6. `Sticky-left · depth N+` 不再作为用户可见 UI。

### 响应式

- 280px：隐藏低价值 metadata，只保留轨道、角色和摘要。
- 520px：显示 label、摘要和简短时间。
- 720px：可显示 model/tool metadata，但不能改变正文起点。
- 长文本只截断内容区域，轨道、marker 和 disclosure 永不压缩。
- 移动端沿用 overlay Sidebar，但保持同一状态机和键盘语义。

## 性能要求

- 目标夹具：1,000、5,000、10,000 entries。
- 规范化树和 visible projection 使用 `Map/Set`，避免 `findIndex` 嵌套导致 O(n²)。
- 搜索文本可按 entry ID 缓存。
- 大于阈值时使用虚拟列表；虚拟化不得破坏 ARIA level、焦点恢复和轨道连续性。
- entries、labels、activeLeaf 未变化时 snapshot 引用保持稳定。

## 验收标准

### 树形正确性

- [ ] GIVEN 单子链，WHEN 渲染，THEN 正文不会随每条消息持续向右漂移。
- [ ] GIVEN 多子分支，WHEN 渲染，THEN 非末兄弟使用 `├` 且竖轨持续到下一兄弟。
- [ ] GIVEN 最后兄弟，WHEN 渲染，THEN 使用 `└` 正确收口。
- [ ] GIVEN 嵌套分支，WHEN 渲染，THEN 每一层祖先轨道连续且无悬空线。
- [ ] GIVEN 搜索/过滤隐藏祖先，WHEN 渲染，THEN 节点连接到最近可见祖先并重新计算轨道。
- [ ] 前缀 golden output 与 Pi TUI/export 逐字符一致。

- [ ] 折叠节点显示隐藏 descendants 数量。
- [ ] active leaf 的祖先始终可见。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| prefix 字符在非等宽字体错位 | prefix 独立使用 mono 字体和固定 `white-space: pre` |
| 虚拟化破坏焦点 | controller 持有 focusedId，渲染后恢复可见焦点 |
| 搜索与折叠状态互相覆盖 | 用户折叠与搜索临时展开使用两套 Set |
| 快捷键与浏览器/应用冲突 | 先通过现有 shortcut registry 审计，再绑定 |
| active leaf 更新导致用户浏览位置跳走 | 仅在 focusedId 无效时回退，不强制跟随 active leaf |
| 过滤后轨道暗示错误真实父子关系 | visibleParent 明确为投影关系，必要时使用弱化 connector 提示跨级 |

## 关键决策

| 决策 | 理由 |
|------|------|
| 先重构 Sidebar，暂不改 Flow/Hierarchy | 限制范围，先建立可信 SSOT 模型 |
| 逻辑层输出 prefix/segments | 防止 UI 和 CSS 再次错误推导树结构 |
| 单击选择、Enter 打开 | 避免浏览树时意外改变对话位置 |
| 普通单子链不增加缩进 | 对齐 Pi，减少深会话横向漂移 |
| 取消常驻详情面板 | 树导航是 Sidebar 的主任务 |
| 搜索结果切换不自动导航 | 保持焦点移动与打开动作分离 |
