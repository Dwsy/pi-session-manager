# Issue: 发布 0.7.1

## Goal

将当前已验证的本地界面与扩展改动按职责提交、同步版本至 0.7.1，并推送 `v0.7.1` 触发正式发布。

## 背景/问题

发布工作流原本使用浮动 Rust `stable`。最近一次成功的四平台 v0.7.0 发布使用 Rust 1.97.0；本机 macOS 在不同 Rust/LTO 组合下出现 Tauri 链接器 bitcode 错误，不能用于预测 CI。为消除工具链漂移风险，本次固定工作流至已验证的 Rust 1.97.0。

## 验收标准

- [x] 当前本地界面与扩展代码通过 `pnpm run build`。
- [x] CLI ARM64 release 编译通过，Rust 测试通过，Rust 格式检查通过。
- [x] 发布工作流的桌面和 CLI job 均固定使用 Rust 1.97.0，且 YAML 结构有效。
- [x] 所有版本来源同步为 0.7.1，且 `node scripts/release-version.mjs check 0.7.1` 通过。
- [x] 本地提交已按界面功能、CI、发布记录和版本元数据分组。
- [ ] `main` 与 `v0.7.1` 已推送至 `origin`，发布工作流已启动。

## 实施阶段

### Phase 1: 发布前检查
- [x] 审计工作区、远端分叉和 v0.7.0 发布历史。
- [x] 修复 3 个阻断前端构建的 TypeScript 错误。
- [x] 完成前端构建、CLI release 编译、Rust 测试及格式检查。

### Phase 2: 发布准备
- [x] 固定发布工作流 Rust 版本至 1.97.0。

### Phase 3: 交付
- [ ] 变基并推送 `main`。

## 关键决策

| 决策 | 理由 |
|------|------|
| 固定 Rust 1.97.0 | 此版本已在 v0.7.0 的 macOS、Windows 与 Linux 矩阵中成功发布。 |
| 不修复 Rust 1.97.1 的既存 clippy lint | 发布工作流不执行 clippy，且这些测试/示例 lint 与本次界面发布无关。 |
| 将所有共享面板、工具渲染器和样式调整放入同一界面功能提交 | 新增共享组件与其所有调用方具有直接依赖，不应拆成不可构建的提交。 |

## 遇到的错误

| 日期 | 错误 | 解决方案 |
|------|------|---------|
| 2026-07-27 | 前端构建报 3 个 TypeScript 错误（未使用变量、缺失 children） | 移除无用解构/导入，并允许无正文确认对话框。 |
| 2026-07-27 | 本机 macOS 桌面 release LTO 链接报 `_EMBED_INFO_PLIST` 重复与 bitcode 错误 | 认定为本机链接环境差异；固定 CI 至最近已成功验证的 Rust 1.97.0。 |
| 2026-07-27 | Rust 1.97.1 clippy 对既有测试/示例报 12 个新 lint | 记录为非 CI 阻断项，不扩大本次发布范围。 |

## Notes

- 本机 Node 22.12.0 低于 pnpm 11.5.2 的最低要求；上一次成功 Actions 实际使用 Node 22.23.1。
- 当前分支与 `origin/main` 分叉：本地领先 1 个提交，远端领先 1 个 README 更新提交；提交后需变基再推送。
