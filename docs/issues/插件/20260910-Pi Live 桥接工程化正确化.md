# Issue: Pi Live 桥接工程化正确化

## Goal

基于 `@earendil-works/pi-coding-agent` 最新发布版（当前 registry latest: 0.85.1）的真实 ExtensionAPI 与 PSM 当前实现，让 Pi Live 的双向事件、session state 与 RPC 控制具备一致、可并发验证、可回归的工程正确性。

## 背景/问题

当前调用链横跨 Pi AgentSession、`pi-session-bridge`、PSM WS/HTTP realtime、Rust registry/commands 和前端 `usePiLive`。源码审计确认 Rust realtime 仍承担协议解析，且文档中曾存在已删除 `ws-bridge.ts` 的路径漂移；本轮以 `@earendil-works/pi-coding-agent` 0.85.1 的 API、事件 payload、并发 RPC correlation 与前端状态计数为真实语义基准。

## 验收标准 (Acceptance Criteria)

- [x] WHEN Pi session 注册、状态更新、live event 或断开，WS 与 HTTP realtime SHALL 对 registry、广播事件与前端 payload 保持等价语义。
- [x] WHEN 同一 session 存在并发 RPC，系统 SHALL 为每个调用生成可区分 correlation id，且 response 只完成匹配调用。
- [x] WHERE bridge 调用 Pi，系统 SHALL 只依赖当前 `@earendil-works/pi-coding-agent` 0.85.1 支持的 ExtensionAPI/事件，并正确处理 prompt、steer、follow-up、model、thinking、commands、abort。
- [x] WHEN live event 被重复/交错转发，frontend SHALL 不产生错误的 entry count 或 streaming 状态漂移。
- [x] WHERE 本任务修改代码，系统 SHALL 通过对应定向测试、格式/类型/构建检查，并保留完整验证命令与结果。
- [x] IF 文档与真实代码路径/协议不一致，THEN SHALL 同步修正文档，不保留失效 `ws-bridge.ts` 等路径作为当前实现。
