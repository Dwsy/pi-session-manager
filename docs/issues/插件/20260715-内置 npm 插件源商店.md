# Issue: 内置 npm 插件源商店

## Goal

在 PSM Web GUI 的 Plugins -> Marketplace 中内置一个基于 npm 的插件源卡片，首个源是 `pi-session-manager-plugin` 套件；用户添加来源后自行选择要启用的 `psm.extensions` 子插件。

## 背景/问题

PSM 现有 Marketplace 只提供通用 npm 搜索。虽然 `pi-session-manager-plugin` 已是多子插件包，但它没有被 PSM GUI 作为内置、可发现的来源展示，用户无法理解它是一个套件或一键安装该来源。

## 验收标准 (Acceptance Criteria)

- [x] Marketplace 在网络搜索前展示内置 npm 插件源区域。
- [x] 内置来源卡说明 npm 包、套件说明和它提供的子插件。
- [x] 点击添加来源使用既有 `install_psm_plugin` npm 受控路径，不引入新下载通道。
- [x] 子插件默认不启用；来源卡按运行时快照展示子插件，用户可逐个启用或停用。
- [x] PSM 来源卡与 Pi Context Navigator 覆盖 `en-US`、`zh-CN`、`de-DE`、`es-ES`、`fr-FR`、`ja-JP`。
- [x] 设置单测、前端构建、插件包测试、类型检查和打包检查通过。

## 实施阶段

### Phase 1: 规划和准备
- [x] 审查现有 Marketplace 搜索、受控 npm 安装及插件运行时刷新路径。

- [x] 决定采用前端内置的受审核来源目录，复用既有 npm 安装 API。

### Phase 3: 验证
- [x] 运行 PSM 插件设置组件测试和 TypeScript 检查。
- [x] 构建前端生产包。
- [x] 审查变更未绕过 npm 包名校验或受控安装目录。

## 关键决策

| 决策 | 理由 |
|------|------|
| 来源目录内置于 PSM 前端 | 这是产品策展数据，不是第三方远程索引；无需新增后端网络信任边界。 |
| 安装复用 `install_psm_plugin` | 后端已校验 npm registry 包名、限定安装目录并刷新发现结果。 |
| 来源展示包级套件与子插件清单 | Marketplace 安装/更新以 npm 包为单位，而 PSM 运行时以 manifest ID 管理子插件。 |
