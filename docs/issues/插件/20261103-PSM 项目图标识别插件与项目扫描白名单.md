# Issue: PSM 项目图标识别插件与项目扫描白名单

## Goal

新增内置 PSM 插件 `psm-project-icons`：按项目目录常见标记文件（package.json、Cargo.toml 等）智能识别项目类型，用项目图标替换项目列表的通用文件夹图标；配套后端「项目扫描白名单」机制——PSM 已知项目目录自动授权，无需用户逐个授权。

## 背景/问题

- 项目列表（侧边栏 / Explorer）对所有目录渲染同一个 `FolderOpen` 通用文件夹图标，无法区分 Rust / React / Python 等项目。
- 项目标识扩展点 `ctx.ui.registerProjectIdentityProvider` 已支持 `avatar`（initial/emoji/url），但没有插件按项目类型提供图标。
- 插件沙箱（`plugin_fs` roots）只暴露 `widgets` / `system-prompts`，插件无法读项目目录的标记文件；任意目录扫描需要白名单管控。

## 验收标准 (Acceptance Criteria)

- [ ] WHEN 插件激活，系统 SHALL 提供 `plugin_project_detect` 后端命令，返回 PSM 已知项目目录的检测结果（`path`/`name`/`authorized`/`kind`）。
- [ ] WHERE 检测请求包含非已知项目目录，系统 SHALL 返回 `authorized: false`（不报错、不读盘）。
- [ ] WHERE 目录为 PSM 已知项目（sessions 数据库 `cwd` 去重），系统 SHALL 自动授权扫描（免用户交互）。
- [ ] WHEN 扫描执行，系统 SHALL 只检查目录顶层固定标记目录/文件（含 `src-tauri/` 子目录约定），不递归、不返回文件内容。
- [ ] IF `package.json` 存在，THEN 系统 SHALL 依据依赖键细化 kind（nextjs/react/vue/svelte/angular/node）。
- [ ] WHEN 项目目录存在可识别类型，`psm-project-icons` SHALL 以品牌 SVG 图标（simple-icons，favicon 风格，`url` avatar）替换通用文件夹图标，label/path 行保持不变（emoji 方案已被否决）。
- [ ] WHEN 项目目录不可识别或检测失败，系统 SHALL 保持默认文件夹图标（provider 返回 `null`）。
- [ ] 新命令 SHALL 要求 `projects:read` 权限（默认授予，非 opt-in），权限校验在 Rust dispatch 层执行。

## 关键决策

| 决策 | 理由 |
|------|------|
| 扫描由后端命令统一执行（用户确认） | 最小权限、可审计；插件不获得任意目录读能力 |
| 白名单 = PSM 已知项目（sessions.cwd 去重）自动授权（用户确认） | 与插件实际拿到的项目来源一致，免逐目录授权 |
| 新权限 `projects:read`，默认授予（非 opt-in） | 只暴露固定标记目录的存在性，不读文件内容；避免授权弹窗 |
| kind 归一化在后端、图标映射在插件 | 检测是领域能力（可单测），图标是 UI 偏好 |
| 新建 `psm-project-icons` 而非并入 `psm-project-identity` | 单一职责：机器目录改名 ≠ 项目类型图标 |

## Notes

- 图标使用 simple-icons（CC0-1.0）vendored 品牌 SVG（白字品牌色圆盘，`url` avatar + data:image/svg+xml）；emoji 方案被用户否决（见 rejected.md）。
- provider `resolve` 必须同步，检测在激活时批量完成后缓存；激活后新建项目在重载插件/重启前显示默认文件夹图标（与 psm-project-identity 相同的既有权衡）。
- 已知项目根与请求路径按「分隔符归一化 + 去尾斜杠」精确匹配（大小写敏感），不做前缀包含，防止越权扫描。
