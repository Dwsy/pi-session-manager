# Issue: 划选书签功能（插件化）

## Goal

用户在会话正文中划选文本即可收藏为书签（可附批注），重开会话时原文位置高亮回显，
书签可列表跳转、跨会话全文搜索、AI 主题整理。存储与业务全部落在插件
（`extensions/psm-bookmarks`），host 只新增最小公开 SDK 能力（selection 契约 + 高亮渲染点）。

## 背景/问题

- PSM 现有 `label` entry（JSONL `{"type":"label"}`）只有 entry 级、文本单字段，无划选 range 能力；
  且 JSONL 是 Pi Agent 的写入域，PSM 不应往里写自有数据。
- Plugin SDK 已有 `records`（scope + 全文 + 二级索引）与丰富 UI 贡献点，但缺少：
  1) transcript 划选捕获契约；2) 正文内 range 级高亮渲染点；3) `PsmPluginCommandContext`
  的 `selection` scope 名下没有 selection 数据（名不副实）。
- 用户决策（已确认）：transcript 划选；插件 record + text-quote 锚持久化；范围含高亮回显、
  列表跳转、批注、搜索/AI 整理；允许最小 host SDK 扩展。

## 验收标准 (Acceptance Criteria)

- [x] WHEN 用户在 transcript 单条消息内划选非空文本，系统 SHALL 在选区附近显示浮层，列出插件注册的 selection actions
- [x] WHEN 划选跨多条消息或落在正文容器外，系统 SHALL 不显示浮层
- [x] WHEN 插件 selection action 执行时，host SHALL 传入 `PsmSessionSelection`（sessionPath、entryId、selectedText、textQuote{exact,prefix,suffix}）
- [x] WHERE 插件通过 `records.upsert` 持久化书签（scopeType=session），记录 SHALL 含 text-quote 锚、quote、note、createdAt 且可 `records.search` 全文检索
- [x] WHEN 重新打开含书签的会话，系统 SHALL 通过 highlight provider 恢复原文位置高亮（text-quote 重定位）；锚定失败时降级为 entry 级标记且不报错
- [x] WHEN 同一 entry 内存在重复文本，锚定 SHALL 用 prefix/suffix 消歧命中正确片段
- [x] WHEN 用户点击高亮，系统 SHALL 打开插件 `renderPopover` 提供的浮层（批注查看/编辑/删除）
- [x] IF 插件在旧版 host（无 selection 能力）加载，THEN 书签数据层与面板仍可用（entry 级跳转），划选入口静默缺失
- [x] WHEN 运行 `pnpm exec vitest run`（相关用例）与 `pnpm run typecheck:extensions`，SHALL 全部通过

## 关键决策

| 决策 | 理由 |
|------|------|
| 书签存 plugin record（scopeType=session），不写 JSONL label entry | JSONL 是 Pi Agent 写入域；record 有 schema 版本、二级索引、全文检索，划选 range 是 entry 级 label 表达不了的 |
| 锚定用 W3C TextQuoteSelector（exact+prefix/suffix），不存 DOM Range/字符偏移 | markdown 渲染、流式更新、模板变化使偏移失效；text-quote 对渲染差异鲁棒，可消歧重复文本 |
| selection action 由 host 渲染统一浮层按钮（`run` 回调），不给插件 DOM | 浮层 UX 一致性、安全边界（插件不碰宿主 DOM），对齐 Capability Audit 哲学 |
| 高亮渲染点走 `renderPopover` 插件浮层 | 批注的查看/编辑/删除是插件业务，host 只负责 range 定位与浮层容器 |
| v1 划选限单条消息内 | 跨消息锚定需多 entry 聚合与拆分语义，收益低复杂度高（YAGNI） |
| scopeId 用 session path | 与现有 records 用法一致；rename 失联风险接受（书签随会话文件，rename 命令本身是 host 私有面） |

## 结构图

```text
[用户划选 transcript] → host SelectionOverlay (mouseup→entryId→TextQuoteSelector)
        → 插件 selection action.run(PsmSessionSelection)
        → records.upsert(scope=session, payload{anchor, quote, note})
重开会话 → host 调 highlightProvider.resolveHighlights → textQuote 重定位 DOM Range
        → wrap <mark> + hover tooltip；点击 → renderPopover 浮层（批注编辑）
列表跳转 → panel → viewer.revealEntry(entryId) → 滚动到高亮
搜索/AI → records.search / ctx.psm.agent.run → App 视图聚合
```

## 品质迭代（2026-11-12 第五轮 · 大纲树透明叠字与视觉层级）

用户第三张截图：大纲面板段头与条目行文字叠在一起，且整体 tree 结构「太不高级 / uiux 很 low」。

**根因（确认为低级错误）**：`.branch-segment-row` 背景 `rgb(var(--color-card) / 0.72)`、sticky 头 `/ 0.96`、各叠加态 `/ 0.34~0.58`。虚拟列表里行是 `position: absolute` 层层叠放，任何 alpha 都会让下面那行文字穿透上来。内容层不该有 alpha。

设计评审（Before / After / Why）：

| Before | After | Why |
| --- | --- | --- |
| `background: rgb(var(--color-card) / 0.72)` 段头 + `/ 0.96` sticky | `var(--branch-surface)` / `var(--branch-surface-raised)` 全不透明 | 虚拟列表上层绝不能透；这是叠字的直接原因 |
| `is-active-path` / `is-match` 用 alpha 叠色 | `color-mix(in srgb, surface 88%, accent)` 混出不透明色 | 强调态也要不透明，否则选中行照样叠字 |
| 40px 等宽行、两行小字全灰 | 44px 行高、主行 `foreground` / 元信息 `faint` 分级 | 信息层级靠对比度而非字号堆叠；给两行内容呼吸 |
| 段头只是「又一条记录」 | small-caps 段标签 + 前置 accent 竖条 + 实心 code chip | 章节与条目一眼可分，树才有结构感 |
| 引导线是贯穿到底的 1px 灰线 | 每条 active rail 加节点圆点，active path 实心放大 + ring | 从「一根线」变成「一棵有节点的树」 |
| 通用 ease 过渡 | 140ms `cubic-bezier(0.23,1,0.32,1)`，`:active` 轻微变色 + fold `scale(0.9)` | 明确的 ease-out 与按压反馈；高频交互不做花哨动效 |
| 状态 `ACTIVE/PATH` 淡底方块 | 实心胶囊 chip，`FORK` 圆角描边 | 状态是稀缺信息，应该跳出来而不是融进背景 |
| 无 reduced-motion 处理 | `@media (prefers-reduced-motion)` 关闭过渡与按压位移 | 保留颜色反馈、去掉运动，符合可访问性 |

**验证**：新增 `SessionTreeStyles.test.ts`（10 用例，编译真实 less 后断言 8 个内容层背景不含 alpha、sticky 层级存在、`ROW_HEIGHT` 与 CSS 行高一致），并做了变异测试——把 `0.72` 塞回去 2 个断言立刻失败，还原后全绿。`SessionTree.test.tsx` 16 用例、`tsc --noEmit`、less 编译、`pnpm run build` 全通过。

> 教训升级：这次连「透明」这种肉眼一眼可见的问题，都是靠用户第三张截图才发现的。补的静态断言盯的是**编译后的 CSS**，因为源码里看着不透明、`color-mix` 和变量展开后透不透是另一回事。

## 品质迭代（2026-11-12 第六轮 · 去掉大面积主题色铺底）

第五轮为了「不透明 + 有强调」，给 `is-active-path` 写了 `color-mix(surface 88%, accent)`。但线性会话里**几乎每一行都在 active path 上**，而主题 accent 是 `#0d9488` 青绿——结果整个大纲面板被染成一片绿，用户第四张截图反馈「绿色背景很干扰」。同样的问题还出现在搜索命中行（warning 混底）、`:active` 按压、段头实心绿 code chip、实心绿状态胶囊。

修正原则：**背景一律中性，强调只落在结构线/边框/文字上**。

| Before | After | Why |
| --- | --- | --- |
| `is-active-path` 用 accent 混色铺满整行 | 中性 `--branch-surface` + 左侧细 ring 竖条 | 路径是结构状态，靠树轨节点与竖条表达就够，不需要整片染色 |
| `is-match` 用 warning 混色铺底 | 抬起的 neutral surface + warning 左竖条 | 搜索命中是稀疏信息，不该引入第二种大面积色块 |
| `:active` 混 18% accent | 纯中性 `--branch-surface-sunken` | 按压瞬间不该闪一片绿 |
| 段头 code chip / 状态 chip 实心 accent | 中性底 + 描边 + accent 文字 | 绿只在小面积文字/边框上，退成点缀 |

新增静态断言「任何树行背景不得 `color-mix(...) var(--accent)`」，并做变异测试：把混色塞回去该断言立刻失败，还原后 11 用例全绿。过程中发现首版正则 `[^)]*` 会被嵌套 `var()` 截断造成**假绿**，已改用字符串包含判断并重验——测试本身也要验证能抓到 bug。

> 连续两轮的教训：修「透明」时我为了保住强调感，又造出「整片绿」。视觉问题不能只靠"不透明/有对比"这种抽象指标闭环，得盯着真实截图里那块颜色到底占了多大面积。

## 品质迭代（2026-11-12 第七轮 · 大纲单击即跳转）

用户反馈「ux 不好，需要双击才跳转，改成单击」。

原实现把「选中」与「跳转」拆成两种手势：`onClick → selectNode`（仅改高亮）、`onDoubleClick → activateNode`（`onNodeClick` 滚到会话正文）。大纲是导航控件，用户点条目就是想过去，双击属于多余门槛。

改动：`SegmentRow` / `EntryRow` 的 `onClick` 直接接 `activateNode`（它内部已 `setSelectedUid` + `setFocusedUid`，不丢选中态），删除 `onDoubleClick` 与不再需要的 `onSelect` prop；折叠按钮本就 `stopPropagation`，不会误跳。`GlobalMapCanvas` 同样改为单击 `select + activate`，保留 `suppressClickRef` 拖拽抑制，避免平移手势误触发导航。键盘 `Enter` 原本就走 `activateNode`，不受影响。

测试：两个原「双击才跳」用例改为单击断言（含「点较早分支节点跳到最新末端」），新增静态断言钉住列表与画布都不得再出现 `onDoubleClick` / `handleDoubleClick`。全量 1138 用例通过、`tsc --noEmit`、`pnpm run build` 通过。
