# Issue: 划选书签功能（插件化）

## Goal

用户在会话正文中划选文本即可收藏为书签（可附批注），重开会话时原文位置高亮回显，
书签可列表跳转、跨会话全文搜索、AI 主题整理。存储与业务全部落在插件
（`extensions/psm-bookmarks`），host 只新增最小公开 SDK 能力（selection 契约 + 高亮渲染点）。

## 背景/问题

- PSM 现有 `label` entry（JSONL `{"type":"label"}`）只有 entry 级、文本单字段，无划选 range 能力；
  且 JSONL 是 Pi Agent 的写入域，PSM 不应往里写自有数据。
- Plugin SDK 已有 `records`（scope + 全文 + 二级索引）与丰富 UI 贡献点，但缺少：
  1) transcript 划选捕获契约；2) 正文内 range 级高亮渲染点；3) `PsmPluginCommandContext`
  的 `selection` scope 名下没有 selection 数据（名不副实）。
- 用户决策（已确认）：transcript 划选；插件 record + text-quote 锚持久化；范围含高亮回显、
  列表跳转、批注、搜索/AI 整理；允许最小 host SDK 扩展。

## 验收标准 (Acceptance Criteria)

- [x] WHEN 用户在 transcript 单条消息内划选非空文本，系统 SHALL 在选区附近显示浮层，列出插件注册的 selection actions
- [x] WHEN 划选跨多条消息或落在正文容器外，系统 SHALL 不显示浮层
- [x] WHEN 插件 selection action 执行时，host SHALL 传入 `PsmSessionSelection`（sessionPath、entryId、selectedText、textQuote{exact,prefix,suffix}）
- [x] WHERE 插件通过 `records.upsert` 持久化书签（scopeType=session），记录 SHALL 含 text-quote 锚、quote、note、createdAt 且可 `records.search` 全文检索
- [x] WHEN 重新打开含书签的会话，系统 SHALL 通过 highlight provider 恢复原文位置高亮（text-quote 重定位）；锚定失败时降级为 entry 级标记且不报错
- [x] WHEN 同一 entry 内存在重复文本，锚定 SHALL 用 prefix/suffix 消歧命中正确片段
- [x] WHEN 用户点击高亮，系统 SHALL 打开插件 `renderPopover` 提供的浮层（批注查看/编辑/删除）
- [x] IF 插件在旧版 host（无 selection 能力）加载，THEN 书签数据层与面板仍可用（entry 级跳转），划选入口静默缺失
- [x] WHEN 运行 `pnpm exec vitest run`（相关用例）与 `pnpm run typecheck:extensions`，SHALL 全部通过

## 关键决策

| 决策 | 理由 |
|------|------|
| 书签存 plugin record（scopeType=session），不写 JSONL label entry | JSONL 是 Pi Agent 写入域；record 有 schema 版本、二级索引、全文检索，划选 range 是 entry 级 label 表达不了的 |
| 锚定用 W3C TextQuoteSelector（exact+prefix/suffix），不存 DOM Range/字符偏移 | markdown 渲染、流式更新、模板变化使偏移失效；text-quote 对渲染差异鲁棒，可消歧重复文本 |
| selection action 由 host 渲染统一浮层按钮（`run` 回调），不给插件 DOM | 浮层 UX 一致性、安全边界（插件不碰宿主 DOM），对齐 Capability Audit 哲学 |
| 高亮渲染点走 `renderPopover` 插件浮层 | 批注的查看/编辑/删除是插件业务，host 只负责 range 定位与浮层容器 |
| v1 划选限单条消息内 | 跨消息锚定需多 entry 聚合与拆分语义，收益低复杂度高（YAGNI） |
| scopeId 用 session path | 与现有 records 用法一致；rename 失联风险接受（书签随会话文件，rename 命令本身是 host 私有面） |

## 结构图

```text
[用户划选 transcript] → host SelectionOverlay (mouseup→entryId→TextQuoteSelector)
        → 插件 selection action.run(PsmSessionSelection)
        → records.upsert(scope=session, payload{anchor, quote, note})
重开会话 → host 调 highlightProvider.resolveHighlights → textQuote 重定位 DOM Range
        → wrap <mark> + hover tooltip；点击 → renderPopover 浮层（批注编辑）
列表跳转 → panel → viewer.revealEntry(entryId) → 滚动到高亮
搜索/AI → records.search / ctx.psm.agent.run → App 视图聚合
```

e2e 发现并修复的缺陷：

1. host：selection/highlight 监听挂载时机（messages 异步挂载时容器 ref 为空）→ 改 document capture + 活 ref。
2. SDK client：`records.upsert` 的 `indexValues` camelCase 与后端 snake_case 不匹配（存量缺陷）→ wire 序列化修复 + 回归测试。
3. 插件：registry 最近列表用 FTS search 读空行永不可见 → 改 `listForScope`。
4. 插件：manifest 缺 `model:invoke`（agent 会话解析模型需要）。
5. host SDK：高亮数据变更无失效信号 → 新增 provider `subscribe` 契约；浮层改数据自感知。

宿主遗留（不阻塞书签功能，已登记）：

- `scripts/pi-model-text.mjs` 使用已被 pi-coding-agent 移除的 `AuthStorage`/`ModelRegistry.create` API → 已修复为 `ModelRuntime` 并实测模型返回 `PONG`。
