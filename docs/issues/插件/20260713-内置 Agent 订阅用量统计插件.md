# Issue: 内置 Agent 订阅用量统计插件

## Goal

新增默认关闭的内置 `Agent Usage` 插件：用户启用并主动刷新后，以独立应用视图展示本机已登录 AI 编程 Agent 的订阅额度、重置时间和可用状态。

## 背景/问题

PSM 现有 Dashboard 只统计本地会话的 token/cost，不能回答各 Agent 订阅周期还剩多少可用额度。参考实现 `muxy-app/extensions/extensions/ai-usage` 支持 14 个本地 Agent/供应商，但它依赖 Muxy 特有的 shell、Keychain 与网络权限；PSM 当前公开插件 SDK 不提供读取任意凭据或发起授权网络请求的能力。

## 验收标准 (Acceptance Criteria)

- [ ] 插件以 `builtin.agent-usage` 注册，`defaultEnabled: false`；未启用时不读取凭据、不联网、也不注册应用视图。
- [ ] 用户启用插件后，可从独立 `/agent-usage` 应用视图和 Cmd+K 命令进入全局统计页。
- [ ] 用户点击“刷新”时，服务端仅使用本机已有登录凭据发起只读额度查询；token 不会写入日志、响应、插件配置或 UI。
- [ ] 首发覆盖参考项目的 14 个来源：Antigravity、Claude Code、Codex、Amp、Copilot、Cursor、Devin、Factory、Grok、OpenRouter、OpenCode Go、Kimi、MiniMax、Z.ai。
- [ ] 每个来源均呈现可用状态、未登录/不可用原因或错误；可用时呈现计划名和一项或多项额度（已用百分比、重置时间、余额）。
- [ ] 已失效 OAuth token 不刷新、不回写凭据；UI 明确提示用户在原始 Agent 中重新登录。
- [ ] 后端命令只能由声明 `usage:read` 的 PSM 插件调用；权限撤销后刷新失败且不进行凭据读取或网络访问。
- [ ] 不支持的操作系统、缺失本地凭据、单个供应商请求失败不会阻断其他供应商结果。
- [ ] 具备 provider 解析单测、权限回归测试、插件视图测试，并通过 TypeScript 和相关 Rust 检查。

## 关键决策

| 决策 | 理由 |
|------|------|
| 默认关闭 + 用户点击刷新才采集 | 凭据读取与外网请求必须显式、可理解、可撤销。 |
| 后端受限采集器而不是浏览器插件直接读取 | 当前浏览器 SDK 无任意文件/Keychain/安全 HTTP 权限；后端可统一最小权限、allowlist、超时和脱敏。 |
| 新增细粒度 `usage:read` 权限 | 不把敏感本机凭据读取混入 `fs:read` 或通用网络权限。 |
| 14 个 provider 使用统一 DTO，适配器彼此隔离 | 单个服务 API/凭据格式变化或失败不影响其它统计。 |
| 禁止 OAuth refresh 与凭据回写 | 用户仅同意读取既有凭据和只读额度请求；不静默修改第三方登录状态。 |
| 独立 App View | 订阅额度为全局信息，不应绑定当前会话。 |

## 风险与待确认

| 风险 | 处理 |
|------|------|
| 第三方私有 endpoint 或本地凭据格式变化 | 每个适配器独立失败并显示诊断；以 fixture 解析测试锁定已知响应。 |
| 部分 API 不返回百分比或重置时间 | DTO 支持余额/值类型，不伪造百分比。 |
| 多平台路径与 Keychain 差异 | 首发以 macOS 已知路径为主；其它平台显示“不支持/未检测到”，不猜测路径。 |
| 14 个实时请求影响体验 | 并发上限、单请求超时、仅手动刷新；后续如需缓存须另行设计。 |
