# PSM 安全与 CI 基线修复

## 背景与目的

关联修复包：`PSM_CODEX_REPAIR_PACKET_2026-07-14.md`。本 PR 在隔离工作树中处理 P0 安全/CI 阻断，并同步完成可验证的 P1 基础迁移。最终发布状态仍需完整 CI、桌面 smoke 和剩余 P1 复验后判定。

## 变更内容

- 认证与 token：移除 loopback 自动免鉴权与 URL token；新增随机 256-bit token、旧固定 token 轮换、Unix 0700/0600 目录/文件权限、原子写入和 fail-closed CSPRNG 失败处理。
- 网络边界：默认 bind 统一为 `127.0.0.1`；增加 trusted proxy / allowed origin / remote terminal 配置模型；限制 CORS；HTTP/WS 精确解析认证消息；默认拒绝网络 terminal capability。
- GUI raw WS terminal gating：`src-tauri/src/server/ws.rs` 捕获握手 `Origin`/`Host`，拒绝不允许的 origin；auth 开启时要求成功认证；terminal 请求还必须显式携带 `terminal_capability: true`，再通过 loopback/remote-terminal 策略。无 Origin 的客户端明确拒绝，不视为可信。
- 客户端契约：`src/transport.ts` 为 terminal 命令附加 `terminal_capability: true`，非 terminal 请求保持不变。
- Markdown/Tauri：引入 DOMPurify allowlist，在解析、搜索高亮后和 sink 前清洗；CSP 从 `null` 改为最小策略；关闭 `withGlobalTauri`；移除默认 shell 权限。
- CI/TypeScript：增加 `typecheck`、`test`、`verify`；扩展类型检查范围；修复 wordcloud 声明；CI 使用 pnpm 脚本并执行 Vitest/扩展验证路径。
- 前端与 P1：AuthGate 不再 localhost 放行或网络错误 fail-open；scan_skills 读取 front matter；更新贡献文档；5 处非语义点击目标改为 button；移除 URL token 读取。

## 风险与兼容性

- localhost 无 token、query-string token 和远程 terminal 默认行为均为 breaking change；客户端需在 AuthGate 中输入 token，远程 terminal 需显式 capability 配置。
- 当前 CORS allowlist 默认覆盖本地开发 UI 与 Tauri origin；反向代理用户需显式配置 `allowed_origins` / `trusted_proxies`。
- CSP 和 capability 收缩可能暴露插件或桌面 smoke 回归，需在真实 Tauri 环境继续验证。
- 全量 Vitest 的 4 个失败 suite 尚未归因，因此本 PR 状态保持 draft/BLOCK，不宣称 GO。

## 回滚方案

回滚本 PR 对应提交即可恢复基线；由于 token 迁移会轮换旧固定 token，回滚后需用户重新检查 token 文件与客户端配对状态，不建议回退到不可信网络暴露模式。
