# SessionViewer UX BDD 改进清单

## 背景
当前 `SessionViewer` 在 RPC 模式下存在状态反馈分散、输入可用性不透明、未读提示弱等问题。  
本轮以 BDD（Behavior-Driven Development）方式收敛核心交互，先保障“可理解、可预期、可恢复”。

## 场景 1：RPC 状态反馈要单一且可执行
**Given** 用户在 RPC 模式浏览会话  
**When** 出现未连接/切会话中/命令加载失败/发送错误  
**Then** 顶部只显示一个高优先级状态条，并给出明确操作（如“重新连接”“重新加载”“关闭”）

### 验收点
- 同时最多显示 1 条 `rpc-banner`
- 优先级：未连接 > 切会话中 > 发送/模型错误 > 命令列表未加载
- 可操作状态必须附带按钮

## 场景 2：输入区不可用时要说明原因
**Given** 输入框被禁用  
**When** 用户尝试发送消息  
**Then** 在输入区底部看到具体原因（例如“RPC 正在切换到当前会话，请稍候”）

### 验收点
- 输入区底部状态文案持续可见
- 发送中显示“消息发送中...”
- 流式响应中显示“正在响应，可中断”

## 场景 3：用户离开底部后，未读反馈应可量化
**Given** 用户滚动离开底部  
**When** 新消息到达  
**Then** 显示“有新消息 (N)”并累计计数；点击后回到底部并清零

### 验收点
- 未读计数上限 99
- 回到底部后清零
- 自动跟随开启时不增加未读计数

## 场景 4：空会话状态需要明确下一步
**Given** 当前会话没有可渲染消息  
**When** 用户进入会话页  
**Then** 除“暂无消息”外，还应提示下一步动作（RPC 下提示“发送第一条消息”）

## 场景 5：顶部工具栏在窄屏不应挤压错位
**Given** 用户在较窄窗口（含移动端宽度）使用会话页  
**When** 顶部操作按钮较多  
**Then** 按钮应分组并可横向滚动，不出现遮挡与错位

### 验收点
- 操作按钮按功能分组（连接/会话/滚动/管理）
- 窄屏下工具栏可换行并保持可点击
- 低频按钮不影响核心状态信息可见性

## 场景 6：新消息浮层不能挡住输入区
**Given** RPC 模式下输入区固定在底部  
**When** 出现“有新消息”浮层按钮  
**Then** 按钮应自动抬高，避免遮挡输入区

### 验收点
- RPC 模式浮层底部偏移 > 输入区高度
- 普通文件模式保持默认底部偏移
- 点击浮层后仍执行“回到底部并清未读”

## 场景 7：工具调用状态要完整可感知
**Given** RPC 正在执行工具调用  
**When** 工具进入运行/完成/失败  
**Then** 用户应看到连续状态变化与基本耗时，且完成后短暂保留结果便于确认

### 验收点
- 运行中工具默认展开，显示“等待工具输出”占位
- 成功工具在消息落盘后不再重复显示（避免与 Bash/Tool 卡片双重渲染）
- 失败工具保留短时间（约 20s）后自动清理
- 状态文案使用中文（运行中/已完成/失败）
- 有 `startedAt/finishedAt` 时展示耗时

## 场景 8：底部自动跟随要有容错区
**Given** 用户已经在会话底部附近阅读  
**When** 新消息到达  
**Then** 应继续自动跟随，而不是误判为“离开底部”

### 验收点
- 采用“底部容错区”判定自动跟随
- 容错区包含 `2.5vh` 规则，并有最小像素下限
- 误判减少后，“有新消息”按钮不再频繁闪现

## 场景 9：新会话应先前端占位，首条消息再真实创建
**Given** 用户点击侧栏项目头部的“+”按钮  
**When** 会话尚未发送任何消息  
**Then** 仅创建前端空白会话占位，不立刻调用 RPC 新建会话

### 验收点
- 侧栏立即出现“新会话”占位项，可直接进入输入
- 首次发送时才调用 `new_rpc_session`
- 真实会话创建成功后，自动替换占位会话并切到真实 session 文件

## 场景 10：可在会话页直接设置思考等级
**Given** 用户已进入 RPC 会话  
**When** 需要在同一会话切换推理强度  
**Then** 可通过“思考等级”下拉直接设置 `off/minimal/low/medium/high/xhigh`

### 验收点
- 输入区附近显示“思考等级”控件
- 切换后调用 `set_rpc_thinking_level`
- 进入会话时从 `get_rpc_state` 回填当前等级

## 场景 11：模型与思考设置应贴近输入区
**Given** 用户主要在底部输入区进行连续对话  
**When** 需要切模型或思考等级  
**Then** 设置控件应位于输入区内部同一区域，而非顶部工具栏或单独占一行

### 验收点
- 顶部工具栏移除模型/思考设置
- 输入区内与发送控件同区展示（模型 + 思考）
- 下拉菜单默认向上展开，避免底部输入区遮挡和出屏
- 窄屏下控件不重叠、可点击

## 场景 12：发送模式使用快捷键，不再使用模式按钮
**Given** 用户连续输入 Prompt / Follow-up / Steer  
**When** 在输入框内发送  
**Then** 通过快捷键完成模式切换，不再显示 3 个模式按钮

### 验收点
- `Enter` 发送 Prompt
- `Option + Enter` 发送 Follow-up
- `Cmd/Ctrl + Enter` 发送 Steer
- `Shift + Enter` 换行

## 场景 13：输入区应为单层容器，避免框中框
**Given** 用户长期停留在输入区进行会话  
**When** 调整输入区视觉密度  
**Then** 使用单层主容器 + 内联控件，避免“框框套框框”造成拥挤感

### 验收点
- 输入文本区域为无边框/透明内层
- 底部动作区与模型/思考/上下文指示器内联
- 模型与思考触发器使用轻量文本按钮风格
